# EXPLICIT

## 一句话问题

系统要在人的工作里替人做事，却没有任何端到端数据能证明它做对了；而 2026-10-23 他当面给的判断把问题又推深了一层：**它连"人到底在做什么"都拿不到**——他的屏幕是一个终端，里面是他跟 agent 打的字，而那个终端对 AT-SPI 不发布任何文本（读数见 [3_REQUIREMENT.md](3_REQUIREMENT.md)）。一个读不到题面、又不会动手的东西，说什么都只能靠猜。

## 谁疼、疼在哪

- 用户本人：单人研究/工程工作者，全天与 agent 对话，多数时间处在 auto advance（离开机器、在做别的事）；工作时他的屏幕多数就是一个终端，跟 agent 一句一句打长文本。【来源：用户自述；2026-10-23 那次方向谈话见本文「目标用户：可观察记录」】
- 疼点一：完全没有端到端数据，任何"它懂我"或"它帮上忙"的说法都无从检验。【来源：用户自述】
- 疼点二（矛盾）：最容易获得数据的场景，恰好是最不可能被接管的任务。【来源：用户自述】
- 疼点三（2026-10-23 新增，也是当前最痛）：**对着他的屏幕说话，本来就没有可说的话**。屏幕里没有富内容，只有他与 agent 的字；真正值得说的东西在屏幕之外（仓库、文档、公开资料）。"能替你做"在这个环境里不可达——终端既不可读也不可写；而一个声称能动手却从不动手的助手，读起来就是低质量。【来源：用户自述 2026-10-23；实测见 [3_REQUIREMENT.md](3_REQUIREMENT.md)】
- 用户的判断：用 agent 监督 agent 在开放研究任务上不可行，其 harness 约 90% 决策自动、10% 需人工 pilot。【来源：用户自述】

## 他说过的现状

- 用户全天在 agent 会话里，人类行为因此稀疏，均匀采样必然大量采到无人的画面。【来源：用户自述，与 screen-only 数据一致】
- 采集覆盖面还停在一个传感器上，GitHub 只是外部 observe 的一条通道，不是主观察路径。【来源：用户自述，与 screen-only 数据一致】

## 目标用户：可观察记录（2026-10-23，在场，深谈过一次）

一条一行，写**场合 + 可观察的证据**，不写对人的评语；同一件事不在别处写第二遍。来源标记只有三种：`用户自述` 是他说的话，`实测` 是我读到的，`推断` 是我从两者推的。

- **他的屏幕内容对他自己没什么可看的**：多数时候就是一个终端里跟我（以及别的 agent）打长段文字。来源：用户自述，2026-10-23。
- **他跟 agent 的对话是长文本、多轮、跨天**：他描述"我们讨论了很多"。来源：用户自述，2026-10-23；与本仓 `trajectory/` 里逐日增长的长对话一致（实测）。
- **他判断这个产品"瞄准错了、质量低"**，理由是：屏幕没有可评的东西；"能替我做"从没真做过；严肃质量要靠外部材料。来源：用户自述，2026-10-23。这是方向，不是缺陷清单。

- **他对"建议"的容忍度远高于"代做"**：可以提建议，但不要声称能做事。来源：用户自述，2026-10-23。
- **他的屏幕在他眼里只是"AT-SPI 能不能工作"的一个例子**：他关心的不是这个屏幕的内容，是这条通道成不成立。来源：用户自述，2026-10-23。

## 由我们定的非目标（他拍板的那一条在 EXPLICIT）

- 开放研究任务上的自动接管：人类 pilot 占比见上时不可行，只做人类 pilot 的辅助，不承诺接管；不声称接管的纪律住在 [0_ROADMAP.md](0_ROADMAP.md) 的非目标里。
- **对着一个空屏幕硬说话**：屏幕没有可评的内容时，宁可沉默也不硬凑——凑出来的话比不说话更贵，它教人不再看。
- 没有既有 check 可判定的接管：无法证伪，只能弃权。
- 用户没有表达过的偏好：不可测，不进入画像。
- 按键内容与聊天对象的内容：不采集；痛点在"什么时候可以帮"，不在"知道用户说了什么"。
