# 本节点（backseat 的 roadmap 持有者）

本目录是一个节点：它持有 `backseat` 的 roadmap、决定它下一步做什么、自己派工作包，并且只对上报告一次。

它存在的原因是上一层的缺陷：`root` 直接往这个项目里派包，于是就在项目内部做计划——M0′ 的门槛项被从上面加了一条又被自己撤回，就是这个形状。门槛、拆分与判定人口现在归这里，`root` 只收到报告。

工作顺序的理由：M0′ 之后的每个里程碑都在数同一批语义行，所以先把"这批行站不站得住"变成可复算的东西，再谈 M1′ 的矩阵。M0′ 的判据分两半，可机械判定的那一半（A：引用可解析且在窗内；C：依据在不在行内）现在有命令了，判不了的那一半（B：内容真假）只能靠独立评审；写入器的缺陷不用等任何人就能修，而实跑的读数和通道范围在用户手上，所以顺序是**先落地写入器与尺子，再把实跑等成一条资源报告**。

## 当前事实（决定过的）

- **D1 C 成为门槛项，阈值 0 缺陷（即 100%）**：它数的是"依据在不在行内"，只有两态；低于 100% 就是承认已知缺陷。B 的 95% 是抽样判断，两者不共用阈值。C 的一半（C1 切换句基帧、C2 沿用称呼点名）由 `scripts/d1_census.py` 判，历史行不进判定。
- **判定人口**：A 与 C 只判写入修复之后落库的行（`messages.id` 大于冻结快照的 max small id）；104 行历史缺陷按已知降级保留、不回填。这是执行上一层的裁决（"门槛说的是将来的行"），不是新决定；推翻它要一次回填 + 重抽一次样。
- **`SWITCH_RE` 放宽：是**，但只放到一张**封闭的**词面表（`由…切至`/`切换为`/`画面切至`/`相较上一帧`/`仍为`…），基帧仍只取"模型点名的 `since` 帧，缺省上一条 small 的 `obs_ids`"——不加深度，所以每行最多多一个帧、窗口最多往前多延伸一帧。理由是实测：seed 3371 的 50 行里写入判据只命中 24 行，宽词面命中 47 行，漏掉的 23 行对比句没有任何一行被要求引用基帧。代价（更宽的窗口）记在这里，收益（依据在行内）落在 C 上。
- **称呼记忆要累计**：普查量出 `state["epithets"]` 只记上一行，21,737 行沿用里 20,176 行是跨行沿用，写入器一次也拦不住——评审数到的 17/50 正是这一种。故 BS-M0P-封口 把它改成累计（有界），并让保留的点名进 `payload.cast`。
- **`labels` 不进 M0′**：迁移已获授权，归 M1′；`docs/SCHEMA.md` 已写一行，别处的【待用户确认】已改掉。
- **称呼机制对真模型的量法**：机制侧由测试固定（不合作的模型＝可见拒绝，不是静默沿用）；模型侧**没有**可用的模型调用（`idle-compute` 下不发模型请求），故只有两个事后读数：`payload.epithet_refused` 行数 / 含称呼行数（模型没点名 cast 的比例）、`run.log` 的 `拒绝落行` 数（整行只剩称呼的损失）。这两个数只记不判；判它的是**修复后的一天实跑**（≥200 行），读数在 `docs/RUNBOOK.md` 的验证节。若拒绝率长期 >50%，问题在提示词而不在规则，重开的是提示词而不是规则。
