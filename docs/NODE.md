# 本节点（backseat 的 roadmap 持有者）

本目录是一个节点：它持有 `backseat` 的 roadmap、决定它下一步做什么、自己派工作包，并且只对上报告一次。

它存在的原因是上一层的缺陷：`root` 直接往这个项目里派包，于是就在项目内部做计划——M0′ 的门槛项被从上面加了一条又被自己撤回，就是这个形状。门槛、拆分与判定人口现在归这里，`root` 只收到报告。

工作顺序的理由：M0′ 之后的每个里程碑都在数同一批语义行，所以先把"这批行站不站得住"变成可复算的东西，再谈 M1′ 的矩阵。M0′ 的判据分两半，可机械判定的那一半（A：引用可解析且在窗内；C：依据在不在行内）现在有命令了，判不了的那一半（B：内容真假）只能靠独立评审；写入器的缺陷不用等任何人就能修，而实跑的读数和通道范围在用户手上，所以顺序是**先落地写入器与尺子，再把那一次实跑要的授权报上去**（配额与通道范围在用户手上）。

## 当前事实（决定过的）

- **分母为 0 的项是空真，普查按"不能确立"退出 2**：`scripts/d1_census.py` 现在除了"判定人口为空"，还在 **C1 没有命中行、C2 没有被沿用行**时退出 2（缺值记不能确立，不记 0）。这是复核提的，采纳了：空真不是通过。所以预演库（整行拒收之后 `carried=0`）的普查退出码是 2，不是 0——C2 在那一版规则下**没有分母**。
- **D1 C 成为门槛项，阈值 0 缺陷（即 100%）**：它数的是"依据在不在行内"，只有两态；低于 100% 就是承认已知缺陷。B 的 95% 是抽样判断，两者不共用阈值。C 的一半（C1 切换句基帧、C2 沿用称呼点名）由 `scripts/d1_census.py` 判，历史行不进判定。
- **判定人口**：A 与 C 只判写入修复之后落库的行（`messages.id` 大于冻结快照的 max small id）；104 行历史缺陷按已知降级保留、不回填。这是执行上一层的裁决（"门槛说的是将来的行"），不是新决定；推翻它要一次回填 + 重抽一次样。
- **`SWITCH_RE` 放宽：是**，但只放到一张**封闭的**词面表（`由…切至`/`切换为`/`画面切至`/`相较上一帧`/`仍为`…，`backseat/witness.py` 的 `COMPARISON_MARKERS`）。理由是实测：seed 3371 的 50 行里原判据只命中 24 行，宽词面命中 47 行，漏掉的 23 行对比句没有任何一行被要求引用基帧。
- **缺省基帧只取一帧**（本节点自己的决定，`BS-M0P` 报告第 5 节留的那条）：上一条 small 行里 `ts_wall` 最新的那一帧，不是它整行的 `obs_ids`。原来的"整行并进来"沿连续对比段累积——封口在冻结快照上模拟得 obs_ids 长度 median 6 / p95 26 / p99 41 / 最长 69（今天落库最多 6），窗口向前延伸同样的跨度，B 的评审要看几十帧才能判一行。收窄仍是一步、仍只看模型点名的 `since` 与本库已有行，不加深度。
- **称呼记忆要累计**：普查量出 `state["epithets"]` 只记上一行，21,737 行沿用里 20,176 行是跨行沿用，写入器一次也拦不住——评审数到的 17/50 正是这一种。BS-M0P-封口 已把它改成累计（有界 200），并把保留的点名记进 `payload.cast`；封顶 200 这一条本身已被预演证伪（见下面 C2 的两个缺陷）。
- **端点在跑，门卡在授权**：`127.0.0.1:4000` 上有个 litellm 进程在听（pid 1056812，`ps -o lstart,cmd -p 1056812` 得 2026-10-19 20:36:49 起；它不是 systemd 服务单元——`cat /proc/1056812/cgroup` 是终端临时 scope，`systemctl status litellm` 找不到单元），带 key 的 `/v1/models` 返回 200（`curl -s -o /dev/null -w '%{http_code}' http://127.0.0.1:4000/v1/models -H "Authorization: Bearer $LITELLM_API_KEY"`），`run.log` 里 10-19 06:44 的 `Connection refused` 早于这次启动——"端点没起"是过期证据。所以 `实跑 → 新快照 → 普查` 缺的不是基础设施，是 tokens 的授权（person）与 scope 那一问（见 Roadmap 的工作包 5）。
- **不用本地模型代跑实跑**：机器上有 4090 与 llama.cpp 的多模态权重（`~/hf/*mmproj*.gguf`），跑一次不花钱；但不做：(a) 它要独占 GPU，不在本节点这一轮的授权里；(b) 换模型写出的语义行不构成 B（内容真假）的判断人口，而它一旦落进同一个人口，就把"修复后的行"弄脏了。故门槛要的实跑等产品配置那一次；本轮只做预演（同一批正文、新规则、无模型调用）。
- **C2 还有两个缺陷，预演量出来的（实跑之前就看得见）**：用 `/tmp/slice.db`（旧快照前 3,000 条 small 行）走 `scripts/rehearse_writes.py` 再普查（`/tmp/rehearse-slice.db`）：A 干净（refs 7,130 / 坏 0 / 出窗 0 / 倒置 0）、C1 `recorded=1671 unrecorded=0`、C2 `carried=682` 里有 **336 行静默沿用**。两个原因：
  （1）**同一套归一化没有用在匹配上**：册子用 `epithet_forms`（去“的”、取名词前 2–6 字的后缀变体），`_settle_epithets` 却拿原文 `form in out` 去比；模型写“穿米色大衣的男子”而册里是“米色大衣男子”，匹配不上就不拒。证据：切片第 749 行，当时册里只有 109 个词面（远未到 200），该行仍原样留下“右侧穿米色大衣的男子”，`payload` 里没有 `epithet_refused`。
  （2）**册子封顶 200 个词面，而记录里出现过 15,368 个**（一个名字生 5 个后缀变体）：超过 200 就把旧词面忘了，再写就是静默沿用。证据：切片第 849 行的词面首见在第 37 位，该行已累积 243 个（>200），未拒。
  两项都是 C2 的判定人口缺陷（C2 阈值 0，不是 95%）。包 BS-M0P-称呼册（commit `12ba961`）已修：册子落到库里的 `epithets` 表（不封顶、跨重启仍在）、匹配与拒收用同一套归一化、沿用未点名**整行拒收**（正文不改写），历史由 `scripts/backfill_epithets.py` 回填（幂等）。预演切片重跑：A refs 4,534 全清、C1 577/577、C2 `silent=0`；代价是 1,439/3,000 行（48%）整行不落库。
- **拒收率高有一部分来自后缀变体互相命中**：一个名字生 5 个后缀变体，于是不同人物的共同后缀（如 `大衣男子`）也互相认作同一个称呼——A 的 `红发大衣男子` 出现后，B 的 `黑发大衣男子` 也被判成沿用而整行拒收。这是机制的粒度问题（2–6 字后缀），不是模型没点名。要不要收紧（例如只在“名词前 ≥2 字重叠”才认同一称呼）属于下一个包的口味问题，实跑读数之后再说。
- **48% 是下界，不是实跑会看到的数**：预演的册子从空表起，从不先跑回填；而 RUNBOOK 的实跑三步是"先回填再跑"。真跑时历史词面开跑前就在册里，于是新人口里"首次出现的旧名字"也会被整行拒收——预演里它们被放行了（切片上 76 行人名行全是 fresh）。所以丢弃率只会比 48% 高；按回填后的口径，连那 76 行也要算进去。
- **C2 的零现在是"坏主张不写"的零，不是"证据齐备"的零**：整行拒收之后沿用行不存在，所以切片上 `carried=0`、`desc_rows` 从 882 掉到 76——门槛的 C2 在这一版规则下**没有分母**，它的 0 是空真。要不要接受这个代价（近一半事实不落库）是产品取舍：另一条路是把提词器改成"只描述本帧、不给人物起称呼"（保留行数、删掉这个特性）。两条路都报给上一层，不在这里自己拍。
- **册子必须用历史回填**：C2 的“沿用”是跨全库比（同一词面在更早的 small 行里出现过），所以修复后第一次重写历史里的名字也必须被拒；不然实跑的头几百行会把历史里每个名字静默沿用一次。回填必须幂等、且写在 RUNBOOK 的实跑三步里。
- **称呼越帧的处理：整行拒收，不做文本手术**（本节点的决定，包 BS-M0P-称呼册 按它改）：名字的边界在文本里不可知——`epithet_forms` 取的是名词前那段连续汉字的后缀，最长变体会把邻词一起吞掉。预演库里已经能看见后果：输入「画面从带“ever”水印的剧集男子近景切换为红发男子对着立式麦克风的近景」写出后变成「…剧集男子近对着…」——「景切换为红发」被删，连对比句标记词「切换为」一起消失（切片输入侧标记行 1,682，写出后只剩 1,671，差的那 11 行就是被吃掉的标记词）。所以改成：正文里出现**被沿用**的词面、而它没在 `cast` 里点名本轮某张图 → 整行不落库、计数、日志留一行；正文一个字节不改，就不会有半个名字或被吃掉的标记词。**首次出现**的词面照旧放行（SCHEMA 已写）。代价是“重写历史里旧名字的行会被丢”的数量变大，这个数由实跑读数出（`拒绝落行`），提词器是它的杆杆。
- **标题字段化：这一轮不做**（M0′ 的可选增强）。数据不是凭空要的：`observations.meta` 已有 868 帧带 `window_switch`（`SELECT count(*) FROM observations WHERE meta LIKE '%window_switch%'`），所以列化的路子是"从 meta 提列 + 让写入路径给每帧标题"。不做的理由：它的消费者是 M1′ 的基线（"只看窗口标题序列"），而它要动 observations 的写入路径——正在等的那次实跑要的是干净的判定人口，在它前面改写入面是拿门槛换一个 M1′ 的便利。重开于：实跑落地、M0′ 判完之后。
- **`labels` 不进 M0′**：迁移已获授权，归 M1′；`docs/SCHEMA.md` 已写一行，别处的【待用户确认】已改掉。
- **称呼机制对真模型的量法**：机制侧由测试固定（不合作的模型＝可见拒收，不是静默沿用）；模型侧**没有**可用的模型调用（`idle-compute` 下不发模型请求），故只有一个事后读数：`run.log` 里 `整行拒收` 的行数 / 该时段写入的 small 行数（模型没在 `cast` 里点名的比例；轨迹里见证调用 24,553 次、带 `cast` 的 0 次——`grep -h -o '"purpose": "witness[^"]*"' ~/backseat-data/trajectory/*.jsonl | wc -l` 与 `grep -h -c '"cast"' ~/backseat-data/trajectory/*.jsonl | paste -sd+ | bc`——所以现在会很大）。这个数只记不判；判它的是**修复后的一天实跑**（≥200 行），读数在 `docs/RUNBOOK.md` 的验证节。若拒收率长期 >50%，问题在提示词而不在规则，重开的是提示词而不是规则。
