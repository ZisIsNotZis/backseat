# 本节点（backseat 的 roadmap 持有者）

本目录是一个节点：它持有 `backseat` 的 roadmap、决定它下一步做什么、自己派工作包，并且只对上报告一次。

它存在的原因是上一层的缺陷：`root` 直接往这个项目里派包，于是就在项目内部做计划——M0′ 的门槛项被从上面加了一条又被自己撤回，就是这个形状。门槛、拆分与判定人口现在归这里，`root` 只收到报告。

工作顺序的理由：M0′ 之后的每个里程碑都在数同一批语义行，所以先把"这批行站不站得住"变成可复算的东西，再谈 M1′ 的矩阵。M0′ 的判据分两半，可机械判定的那一半（A：引用可解析且在窗内；C：依据在不在行内）现在有命令了，判不了的那一半（B：内容真假）只能靠独立评审；写入器的缺陷不用等任何人就能修，而实跑的读数和通道范围在用户手上，所以顺序是**先落地写入器与尺子，再把那一次实跑要的授权报上去**（配额与通道范围在用户手上）。

- **C2 还有两个缺陷，预演量出来的（实跑之前就看得见）**：用 `/tmp/slice.db`（旧快照前 3,000 条 small 行）走 `scripts/rehearse_writes.py` 再普查（`/tmp/rehearse-slice.db`）：A 干净（refs 7,130 / 坏 0 / 出窗 0 / 倒置 0）、C1 `recorded=1671 unrecorded=0`、C2 `carried=682` 里有 **336 行静默沿用**。两个原因：

  两项都是 C2 的判定人口缺陷（C2 阈值 0，不是 95%）。包 BS-M0P-称呼册（commit `12ba961`）已修：册子落到库里的 `epithets` 表（不封顶、跨重启仍在）、匹配与拒收用同一套归一化、沿用未点名**整行拒收**（正文不改写），历史由 `scripts/backfill_epithets.py` 回填（幂等）。预演切片重跑：A refs 4,534 全清、C1 577/577、C2 `silent=0`；代价是 1,439/3,000 行（48%）整行不落库。
- **拒收率高有一部分来自后缀变体互相命中**：一个名字生 5 个后缀变体，于是不同人物的共同后缀（如 `大衣男子`）也互相认作同一个称呼——A 的 `红发大衣男子` 出现后，B 的 `黑发大衣男子` 也被判成沿用而整行拒收。这是机制的粒度问题（2–6 字后缀），不是模型没点名。要不要收紧（例如只在“名词前 ≥2 字重叠”才认同一称呼）属于下一个包的口味问题，实跑读数之后再说。
- **48% 是下界，不是实跑会看到的数**：预演的册子从空表起，从不先跑回填；而 RUNBOOK 的实跑三步是"先回填再跑"。真跑时历史词面开跑前就在册里，于是新人口里"首次出现的旧名字"也会被整行拒收——预演里它们被放行了（切片上 76 行人名行全是 fresh）。所以丢弃率只会比 48% 高；按回填后的口径，连那 76 行也要算进去。
- **C2 的零现在是"坏主张不写"的零，不是"证据齐备"的零**：整行拒收之后沿用行不存在，所以切片上 `carried=0`、`desc_rows` 从 882 掉到 76——门槛的 C2 在这一版规则下**没有分母**，它的 0 是空真。要不要接受这个代价（近一半事实不落库）是产品取舍：另一条路是把提词器改成"只描述本帧、不给人物起称呼"（保留行数、删掉这个特性）。两条路都报给上一层，不在这里自己拍。
- **册子必须用历史回填**：C2 的“沿用”是跨全库比（同一词面在更早的 small 行里出现过），所以修复后第一次重写历史里的名字也必须被拒；不然实跑的头几百行会把历史里每个名字静默沿用一次。回填必须幂等、且写在 RUNBOOK 的实跑三步里。
- **称呼越帧的处理：整行拒收，不做文本手术**（本节点的决定，包 BS-M0P-称呼册 按它改）：名字的边界在文本里不可知——`epithet_forms` 取的是名词前那段连续汉字的后缀，最长变体会把邻词一起吞掉。预演库里已经能看见后果：输入「画面从带“ever”水印的剧集男子近景切换为红发男子对着立式麦克风的近景」写出后变成「…剧集男子近对着…」——「景切换为红发」被删，连对比句标记词「切换为」一起消失（切片输入侧标记行 1,682，写出后只剩 1,671，差的那 11 行就是被吃掉的标记词）。所以改成：正文里出现**被沿用**的词面、而它没在 `cast` 里点名本轮某张图 → 整行不落库、计数、日志留一行；正文一个字节不改，就不会有半个名字或被吃掉的标记词。**首次出现**的词面照旧放行（SCHEMA 已写）。代价是“重写历史里旧名字的行会被丢”的数量变大，这个数由实跑读数出（`拒绝落行`），提词器是它的杆杆。
- **标题字段化：这一轮不做**（M0′ 的可选增强）。数据不是凭空要的：`observations.meta` 已有 868 帧带 `window_switch`（`SELECT count(*) FROM observations WHERE meta LIKE '%window_switch%'`），所以列化的路子是"从 meta 提列 + 让写入路径给每帧标题"。不做的理由：它的消费者是 M1′ 的基线（"只看窗口标题序列"），而它要动 observations 的写入路径——正在等的那次实跑要的是干净的判定人口，在它前面改写入面是拿门槛换一个 M1′ 的便利。重开于：实跑落地、M0′ 判完之后。
- **`labels` 不进 M0′**：迁移已获授权，归 M1′；`docs/SCHEMA.md` 已写一行，别处的【待用户确认】已改掉。
