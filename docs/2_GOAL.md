# 2_GOAL — 产品身份与成功度量

本文件定义 backseat 的产品身份、目标与非目标、北极星的方向，以及成功度量的口径（D1–D8 各测什么）。
前提：身份与方向来自用户自述与已定的项目方向；度量口径是判读门槛前的定义。
不在这里：通过阈值住 [0_ROADMAP.md](0_ROADMAP.md)，版本排期住 [0_ROADMAP.md](0_ROADMAP.md)，
操作命令与判定步骤住 [9_IMPLEMENTATION.md](9_IMPLEMENTATION.md)，交互与呈现住 [5_PRODUCT.md](5_PRODUCT.md)。

# EXPLICIT

**产品身份：listener**——它监听而不是和用户对话；屏幕、ATSPI、音频与视频都是监听面，视频通道押后。
【来源：用户自述，2026-10-19 会话】

**它说什么（2026-10-23 方向）**：评论者与人肉建议者——有话说就说，没话说就沉默；**不承诺动作**，也不演一个能替你动手的助手。
上面那条“listen”说的是输入，这条说的是输出，两者不冲突。【来源：用户自述，2026-10-23；记在 [1_PROBLEM.md](1_PROBLEM.md)】

**非目标（当前里程碑，2026-10-23 加严）**：不承诺“替你做”——不发动作、不点鼠标、不敲键盘、不改他的仓库；
出口的 `act` 动词在本里程碑没有消费者，`propose` 只提建议且必须带“依据在哪”。
理由不是洁癖：他的终端对 AT-SPI 一个字节都不发布（实测读数见 [3_REQUIREMENT.md](3_REQUIREMENT.md)），
我们连“他要做什么”都读不全，声称能接手就是把质量压到他一眼看穿的程度。【来源：用户自述 2026-10-23 + 实测】

# INFERRED

**目标（Release 2.0）**：感知层——持续观察，构建分层长期记忆，经出口表达（弹幕）。

**主线（Release 3.0）**：见证者；范围、五条取证通道与里程碑只住在 [0_ROADMAP.md](0_ROADMAP.md)，本文不复制。

**非目标（Release 2.0）**：帮助层（代替用户执行动作）不属于 2.0 的范围；3.0 的非目标以 [0_ROADMAP.md](0_ROADMAP.md) 为准。

**北极星（方向性，不实现）**：个人画像 → 可导出、可联合 → 组织级记忆（A2A），解决集体痛点。
对架构的唯一要求：画像与时间线必须是**一等公民的导出物**，数据模型保持干净。

**物质从哪来（2026-10-23 方向）**：屏幕只给**题面**（在哪个窗口/标签、画面什么时候变、可见片段里出现了什么词），
真正值得说的内容来自**屏幕之外**——仓库、文档、公开资料、他本机的会话记录。
据此，一条表达的来源链是：触发（像素 / AT-SPI 标题）→ 题面（一句话：他在干什么）→ 外部材料（取到什么算什么）→ 评论（只基于取到的东西）。
代价写在这里，不许事后才发现：取材料要**网络**（离线或被墙＝没有材料，那就沉默或降级，不编）、要**延迟**（一条表达不再是秒级）、
会**陈旧**（缓存与索引会过期）、会**认错题**（把 A 项目的材料贴到 B 上，这是最贵的一种错）。
这条改的是产品的价值来源，不是加一个功能：屏幕从“内容”降为“线索”。
【推导，依据：用户自述 2026-10-23 + 传感器实测（见 [3_REQUIREMENT.md](3_REQUIREMENT.md)）】

## 成功度量：D1–D8 各测什么

判定门槛的 D1–D8 各占一条，彼此正交；这里只定“各测什么”。
通过阈值住 [0_ROADMAP.md](0_ROADMAP.md) 各门槛行；判定人口与命令（含退出码）住 [9_IMPLEMENTATION.md](9_IMPLEMENTATION.md)。

**D1（语义回指率）测什么**：三个彼此正交的分项——引用管道、内容真假、依据是否在行内。
- **A 引用可解析且在窗内**：每条 small 行的每个 `obs_ids` 成员，id 在 observations 里存在，
  且该观察的 `ts_wall` 落在本行 `[ts_start, ts_end]` 内。它测引用管道，不测内容真假。
- **B 断言与帧相符**：独立评审逐行看 `obs_ids` 指向的帧，判“该帧支持该行的语义断言”。
  它测内容真假，测不到“断言的依据是否就在本行 `obs_ids` 里”。
- **C 依据在不在行内**（第三条），分两个可机械判定的项：
  C1＝内容命中对比/过渡词面的行，`payload.switch_base` 非空且 ⊆ 本行 `obs_ids`；
  C2＝**被沿用**的通行称呼（同一词面在更早的 small 行里出现过）必须带 `payload.cast` 点名的帧，
  否则就是静默沿用；被整行拒收的**不是**缺陷（行不存在，就不存在被放过的主张），静默沿用才是。
  首次出现的称呼不算沿用：它只可能来自本帧，要求它点名等于要求模型说废话（前提是本轮有帧）。
  **分母为 0 就是不能确立**：若 C1 一行都没命中、或 C2 没有一条被沿用的称呼，项没有行可判（空真不是通过）。
- A/B/C 正交——B 全过仍可能依据落在上一条消息的帧里，C 全过也不替 B 证明内容为真。

**D2（题集指标）测什么**：每题一个 exact-match 判定，时间类题目允许 ±60s 容差，其余字符串规范化后相等。
准确率＝答对题数/总题数。引用正确率＝通过的 evidence 条数/引用总条数；
单条引用通过＝被引单元在库中真实存在且持有引用声明的值、该题 `check_sql` 复算得到与答案相同的值、且该引用的时间落在答案所述区间。
“绝对点”是百分点差这一单位：本法准确率与最强基线准确率之差；被测量指标名固定为“语义状态预测准确率”。

**D3（过度自信率）测什么**：在系统自报置信 c ≥ 0.8 的题目中答错的比例。
若系统不产出逐题置信，该里程碑判不通过，不得用代理量替代。

**D4（撤销率）测什么**：台账中 status ∈ {reverted, user_edited} 的接管动作数 / 接管动作总数。
每次接管动作必须记录 commit SHA 与 diff；用户事后 revert 或改动同一文件即计入。无回归＝接管后既有测试与 check 仍全绿。

**D5（可核对率）测什么**：提议总数中“按其引用可在 5 秒内由 check_sql 证实或否证”的比例；不可核对者记为不通过。

**D6（跨重启一致率）测什么**：同一题集在每次进程重启后重跑，答案与重启前相同的题数 / 总题数。

**D7（扰动敏感度）测什么**：对同一批题施加扰动（打乱时序、替换窗口/事件 key、插入无关帧、截断历史）后，
答案发生改变的题数 / 受扰动题数。

**D8（埋雷捕获率与误杀率）测什么**：每批固定＝20 条注入缺陷 + 20 条正确提议，误杀率分母恒为 20。
向提议集注入 20 条已知缺陷（篡改事实、删证据、引用指错帧）；捕获率＝被判出的注入缺陷数/20，
误杀率＝被判为缺陷的正确提议数/正确提议总数。

M4a 的与 oracle 一致率、M5′ 的先审后发与未审即发检出不在 D1–D8 之内，它们在各自里程碑行里就地定义，判据是全称判断或检出记录，不是抽样比例。
