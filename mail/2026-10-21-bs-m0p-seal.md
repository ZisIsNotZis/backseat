## 1. 落地的三处（commit `02a413c`）

**改 1 对比/过渡词面从 `从…切至` 放宽到闭集表** — `backseat/witness.py:63-75`

- `COMPARISON_MARKERS`（五族，逐条注释它收的是评审数到的哪个写法）：
  `switch` = `[由从]…切[至为]`（由/从…切至、由/从…切为）；`bare` = `画面切至|镜头切至|切至|切换为`；
  `contrast` = `相较`（含相较上一帧/相较前帧）；`still` = `仍[为是]|仍保持`；
  `different` = `与此前…不同|相对上一`。
- `SWITCH_RE` 仍是一个模块级 regex，由这张表拼出来（`witness.py:75`），注释写明"表是封闭的、
  只收评审数到的族、放宽的是哪些行欠端点而不是端点从哪来"。`scripts/d1_census.py:41` 照旧 import
  `SWITCH_RE`，没有第二个事实源。
- `_switch_base`（`witness.py:262`）用这条 regex，基帧来源一点没动：点名 `since` 帧优先，
  否则上一条 small 的 `obs_ids`；没有更深搜索。

**改 2 称呼册改成累计（有界）** — `witness.py:89, 104-112, 336-340`

- 新增 `EPITHET_MEMORY = 200` 与 `remember_epithets(known, kept)`：本次用到的词面排到最末、
  旧的保留、超出 200 先忘最久没用过的；结果照旧写回 `state["epithets"]`（跟着库活）。
- `_settle_epithets` 改为 `known = state["epithets"]` + `set_state(remember_epithets(...))`；
  拒绝机制一字未动（正文删掉 → `payload.epithet_refused` → `stats["epithet_refused"]` → 日志），
  只是册子不再是"上一行"。

**改 3 保留的点名进 `payload.cast`** — `witness.py:339, 362-374`

- `attributed` 现在存 `(name, frame)` 对；`retained = [{"name": n, "frame": f} … if n in out]`

## 5. 我解不了的那一条（要你判，不是问）

词面放宽与"基帧照旧取上一条 small 的 `obs_ids`"叠在一起，沿对比句的连续段会**累积**：
每行把上一行的整个 `obs_ids` 并进来。我在冻结快照上按新表、按 id 序做了一次只读模拟
（不改库，只是数据推演）：

```
simulated obs_ids size: max=69 p99=41 p95=26 median=6
marker runs: count=2555 max_run=68  runs>=10: 751
registered obs_ids size in snapshot: max=6
```

即：今天落库的 small 行最多挂 6 个引用（批大小），新表下同一条轨迹会长到 p99=41、最长 69，
窗口随之往前延伸同样的跨度。契约写的是"基帧选择完全照旧，不许加深度搜索"，所以我一个字节都没改；
但这不是"每行最多多一帧"，而是"连续对比段里逐行累加"。要不要把缺省基帧收成"上一条 small 的
**本轮帧**"（仍是一步、仍不看模型之外的东西），是修 A/C1 代价的取舍，属你的 roadmap，不属我的。

另两条只记不判：`state["epithets"]` 现在跨天常驻，200 个词面之后同一个人的称呼只要不点名就一直被拒
（`payload.epithet_refused` 可见），拒绝率是否长期 >50% 要看修复后的一天实跑（NODE 已记的两个读数）；
`payload.cast` 只记录"点名且名字留下"，C2 的"这一行带没带点名"现在读得到，但 C2 的阈值仍等实跑。
